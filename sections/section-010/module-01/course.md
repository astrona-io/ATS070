# Framework Features, Integrations And Application Ownership

This module explains what Backstage is, which features the framework provides, and which work stays with the organization that runs it. It uses a real Backstage application running in a Kubernetes cluster, so every statement can be checked against a running system.

## Learning Goals

- Explain Backstage as an assembled developer portal framework and not as a finished product.
- Distinguish the software catalog, software templates, TechDocs, search and integrations.
- Identify what remains the responsibility of the adopting organization.
- Show from a running application where its configuration, database and ownership information live.

## Before You Start

You should know what a pod, a Deployment and a ConfigMap are. The hands-on part uses a playground with a kind cluster and `kubectl`. Backstage terms are defined where they first appear.

## Reading Order

1. What Backstage Is And How A Portal Is Assembled
2. Catalog, Templates, TechDocs, Search And Integrations
